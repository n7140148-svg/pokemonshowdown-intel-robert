# pokemonshowdown-intel-robert

> **本仓库是「对战机器人工程知识库 / 交接文档」，不是源代码仓库。**
> 目的：让 OpenAI Codex（或任何新接手的工程师/智能体）打开仓库后，能够**零障碍接手 FoulPlay × Metamon 对战机器人的继续开发**——不需要再翻聊天记录、不需要猜测哪些结论已经作废。

**给 Codex 的第一句话**：先完整读根目录的 [`AGENTS.md`](./AGENTS.md)，它定义你的工作约定、红线、命令和文档阅读顺序。然后按 `AGENTS.md` 里的「文档地图」按需读 `docs/`。

---

## 这个仓库里有什么 / 没有什么

**有**：
- 项目本体、三层架构、全部本地路径布局、术语表
- 已落地功能的逐个说明（含所有默认 OFF 的开关及关闭原因）
- 已取得的实战成果：MCTS A/B、Metamon 离线审计、20 局对照、对手建模库统计、测试基线
- **未采用 / 被否决 / 仍在研究**的机器人模型与方案（含辅助形态 A/B、Kakuna、其它 policy 对比）
- 事故台账（490 连败、日志互染、dispatcher 断线、注入污染）与根因 + 修复 + 回归测试
- 环境、工具链、WorkBuddy skills、以及重建 / 下载方法
- 未闭环事项与结论演变台账（**重要**：见下方证据标记约定）

**没有（刻意排除）**：
- 任何 API token、GitHub PAT、Pokémon Showdown 账号密码或登录凭证
- 针对线上服务的攻击研究、威胁建模、渗透手法（那部分是独立的安全研究讨论，不属于机器人工程交付物）
- `E:\Tools\foul-play\logs\` 下的实时对战日志（1.9GB+，会轮转删除，且会干扰正在运行的 bot）
- 任何训练数据 / checkpoint 二进制 / 大体积数据集本体

## 证据标记约定（**Codex 必读**）

本知识库每条事实都带来源标记。汇编与后续维护时**严禁把低等级证据升格为定论**：

| 标记 | 含义 | Codex 应如何处理 |
|---|---|---|
| 【实证】 | 本地日志、实测、命令原始输出可复核 | 可当作事实使用，但改动前建议复核来源文件 |
| 【源码】 | Pokémon Showdown 或 foul-play 源码行号可证 | 可当作事实使用；注意线上版本可能与本地不同 |
| 【推测】 | 原始资料明确标注「未证实 / 疑似」 | **不得当作结论**，不得据此改代码 |
| 【待核】 | 悬案 / 未闭环事项 | 先做验证再动手，不要假设已解决 |
| 【更正】 | 跨文档推翻了更早的结论 | **以更正后口径为准**；旧结论仅作历史留档 |
| 【待确认】 | 无法从本地文件核实的下载地址 / 版本号 | 不要凭记忆填 URL，须向用户索取 |

> **本库存在一条贯穿性的结论演变**：早期（2026-10-23）曾认定「五个 bot 账号全部 userType=10、被匹配墙墙死」，后于 2026-10-25 被逐号实测推翻（thingsyoudo2me=4、iknow_why=4、nutshell93=10，FpConcA/FpConcB 未读）。详见 `docs/11-open-items-and-roadmap.md` 的「结论演变与冲突」章节。**任何涉及账号标记、匹配行为的改动，必须先读该章节。**

## 快速开始（三步）

1. 读 `AGENTS.md`（红线 + 命令 + 文档地图）。
2. 读 `docs/00` 与 `docs/03`（搞清楚「现在是什么状态、哪些开关默认关着」）。
3. 按你的任务去 `docs/11` 查「这件事是不是已知悬案」，再进对应专题文档。

如果要跑测试或改代码，环境与命令在 `docs/01`、`docs/02`；**所有默认 OFF 的开关，打开前必须回 `docs/03` 看关闭原因并取得用户确认**。
